# Low-Altitude-Intelligent-Management
# 低空智慧服务 Web 端项目总览

> 本文用于快速理解项目定位、页面关系、业务流程、权限边界和接口接入方式。  
> 适合作为 README / 项目说明 / 新成员 onboarding 文档。

---

## 1. 项目是什么

`Low-Altitude-Intelligent-Management` 是一个面向正式政务场景的低空智慧服务 Web 端系统。

系统以：

```text
无人机巡查
空间数据分析
问题发现
图斑识别
治理任务流转
执法核查
复核归档
```

为主线，将低空无人机能力与自然资源、林业、农业农村等业务场景结合。

项目当前重点不是“单纯做无人机飞控”，而是构建：

> **从低空巡查发现，到业务问题识别，再到治理闭环的综合低空治理平台。**

---

## 2. 当前首期单位与业务范围

当前系统按单位区分数据域，已有两个单位：

```text
自然资源和规划局
农业农村局
```

不同单位拥有不同业务场景。

示例：

### 自然资源和规划局

```text
林业执法监管
新增违法违规用地智能预警
全程监测存量违法违规用地整改
土地供后巡查与履约分析
土地复垦全流程监管
```

### 农业农村局

```text
耕地种植用途管控与“非粮化”动态监测
种植面积精准核定与惠农补贴监管
塘口全域巡检与“一塘一档”数字建档
长江禁捕全流程闭环执法
高标准农田工程设施管理
高标准农田在建工程管理
```

当前优先完整落地：

```text
林业执法监管
```

# 4. 五个核心业务节点

以林业执法监管为例，完整业务链路为：

```text
低空巡查发现模块                治理模块
航线规划 → 实时巡航       |    图斑识别 → 任务下发 → 复核归档
```

共 5 个节点。

---

## 4.1 航线规划

作用：

```text
决定无人机怎么飞
```

主要内容：

```text
地图
任务巡查范围
当前任务航线
其他历史航线
航点
起降点

航线创建
自动规划
KML 导入
历史航线复用
航点编辑
航线参数
飞行计划日历
```

这个模块是：

> 平台公共能力。

不是林业专属。

---

## 4.2 实时巡航

作用：

```text
查看无人机实际飞行过程和采集情况
```

主要内容：

```text
当前巡查任务
无人机实时位置
飞行轨迹
当前航点
已飞航段
待飞航段

高度
速度
航向
电量
GPS
遥控信号
图传状态

直播画面
采集图片
飞行日志
飞行计划
```

同样属于：

> 平台公共能力。

---

## 4.3 图斑识别

作用：

```text
把巡查成果 / 遥感成果转成可治理的问题线索
```

对于林业工作台，只展示林业相关图斑，例如：

```text
非法侵占林地
毁林开垦
违章搭建
林地占用异常
森林督查图斑
卫片疑似问题
```

页面主要布局：

```text
左：
问题图斑列表 + 缩略图

中：
地图 + 图斑分布

右：
图斑详细信息 + 历史时间轴
```

同时该节点内部包含：

```text
AI 自动识别
多期影像变化检测
2/3/4/5 期影像对比
人工上传变化图片
人工研判
图斑入库
```

注意：

> “变化监测”不再作为独立一级流程节点。

它是“图斑识别”中的一种识别/分析能力。

---

## 4.4 任务下发

作用：

```text
将已确认问题转化成正式核查任务
```

主要内容：

```text
待下发图斑
核查区域
接收单位
接收人员
核查期限
联系人
联系方式
优先级
核查要求
附件
下发记录
```

常见操作：

```text
保存草稿
预览任务
确认下发
批量下发
```

---

## 4.5 复核归档

作用：

```text
接收核查 / 整改成果，完成复核并形成档案
```

主要内容：

```text
整改前影像
整改后影像
无人机复核影像
变化对比

核查结果
整改结果
复核结论
历史流程
归档材料
操作日志
```

操作：

```text
退回补充
复核通过
确认归档
导出档案
```

# 5. 为什么没有“现场核查与整改”独立页面

因为现场核查与整改主要发生在线下/外业。

本系统不需要单独建设一个大页面去模拟外业过程。

系统只需要：

```text
任务下发
 ↓
外业执行
 ↓
结果回传
 ↓
复核归档
```

所以：

> “现场核查与整改”属于后台业务状态，不属于独立一级页面节点。

# 10. 线索来源不是只有无人机

林业问题可能来源于：

```text
无人机巡查
卫片
森林督查图斑
林地占用项目核查
人工上报
其他系统推送
```

因此治理任务不能把：

```text
航线规划
实时巡航
```

强行当作每一条治理任务必经的状态。

工作台顶部显示完整业务链路，是为了：

> 呈现场景整体流程。

而不是表示每条案件一定从航线规划开始。

# 11. 领域工作台的 Header 逻辑

其中：

```text

实时巡航
```

点击后进入公共巡查页面。


```text

新增建设用地预警
```


# 17. 第三方 API 安全边界

禁止：

```text
前端保存 API Key
前端直接签名供应商请求
前端暴露供应商 Secret
```

正式链路：

```text
Vue 前端
 ↓
本系统后端
 ↓
低空大师 API Adapter
 ↓
低空大师
```

# 18. 地图数据约定

推荐统一：

```text
GeoJSON
EPSG:4326
坐标顺序：[longitude, latitude]
```

地图对象：

```text
任务范围 → Polygon
航线 → LineString
航点 → Point
无人机 → Point
问题图斑 → Polygon / MultiPolygon
```

这样前端：

```text
Leaflet
Mapbox
Cesium
```

都容易接。



# 25. Mock 策略

当前阶段仍需保留 Mock。

因为：


所以系统必须支持：


和：

