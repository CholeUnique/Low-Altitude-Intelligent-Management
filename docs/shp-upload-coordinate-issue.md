# 专题 SHP 坐标异常与删除接口（2026-11-27）

## 已复现的原因

本机 `test-area_polygons.shp` 的 PRJ 明确为 WGS84，包围盒中心为 **119.839438037°E、32.482674977°N**。预警专题对象 `TO-20261127-002` 的后端几何却定位于 **115.514121°E、0.000293°N**，面积接近0。

将原坐标当作 **CGCS2000 / 3°带中央经线120°E（EPSG:4549，米）** 转到 WGS84，复算得到 **115.514121132°E、0.000292857°N**，与错误坐标一致。因此该实例符合“经纬度被误当投影米坐标二次转换”，不是网络、底图偏移或正常的 WGS84/CGCS2000 差异。复算证据见 `release/shp-coordinate-diagnosis-20261127.json`。

前端已兼容：解析原始PRJ后，把面几何真正投影至 EPSG:4549，附带匹配的 PRJ 和重建的 SHX；DBF字节不改写、长编号与属性保留，环序、洞及独立面保留。上传前显示实际位置；导入后按来源 datasetId 核对返回对象数量、中心与实际面范围，异常时不报告成功、不自动重试或创建任务。继续导入旧数据集时按海陵区实际行政范围核验，异常数据应删除后重传。

**后端仍应修复原始 SHP 解析**：从 Shapefile schema/PRJ 获取真实源CRS，并固定 X/Y 为经度/纬度或东/北坐标；WGS84经纬度不再按EPSG:4549解释，CGCS2000投影按真实带号/中央经线转换一次。缺少或不支持PRJ时返回明确错误，不静默套用米单位默认投影。几何、面积、中心点须使用同一份正确转换后的数据。已保存的错误数据需从原文件重导或由后端定向修复，不能仅更换前端坐标标签。

## 接口确实支持删除

- `POST /api/v1/biz/upload/delete`，body `{"ids":[数据集ID]}`：逻辑删除数据集，级联删除其上传要素。允许上传人本人、数据部门的一级管理员或ADMIN；越权10107，不存在10201。
- `POST /api/v1/biz/topic/object/delete`，body `{"ids":[专题对象ID]}`：批量逻辑删除本部门专题对象，越权10107。

上传数据集与已导入的专题对象是两份记录，文档未承诺前一个删除级联到后一个。前端提供两个明确入口：上传弹窗的“已保存数据集”中删除数据集；识别页选择上传对象后“删除该上传图斑”。都有确认步骤；已关联任务的图斑由前端拦截，先处理关联业务。删除数据集不会在界面上冒充“关联任务、专题对象全部已删除”。

本次未替用户执行任何删除，也未为验证另建持久业务图斑；使用原文件头、后端页面坐标与离线投影复现进行取证。
