# 高标准农田管理：空间分析接入核查

核查日期：2026-11-03（北京时间）。依据在线 `/v3/api-docs` 和使用真实认证调用的响应。几何测试接口即时计算，不修改业务源图层。

文档入口：[空间分析 / shp 上传对比分析](http://223.2.41.169:8080/swagger-ui/index.html#/智能研判-空间分析/spotCompareUpload)。

## 1. 保留来源的对称差分：可直接实现

`POST /api/v1/spatial/overlay` 仍接收服务和子图层引用；随后 `/overlay/geojson` 传 `merge=false`，返回一个 FeatureCollection，内含裁切后的 `A_ONLY`、`B_ONLY`。两者合起来就是 `(A∪B)−(A∩B)`，不是原始 A、B 图层。

实测输入 A 为服务 9 / 子层 0「高标准农田GBZ」，B 为服务 9 / 子层 1「九龙镇永久基本农田1」，最小面积 4㎡：

- 返回结果编号 19、1195 个差异图斑，只含 `A_ONLY/B_ONLY`，不含交集。
- 仅 A：2,292,254.1165㎡；仅 B：2,020,137.4714㎡。
- `merge=true` 将两个来源合成单个 DIFF，会失去每块结果的所属侧。本轮改用 `merge=false`，仍只显示一个差分结果图层，以两个颜色分类。
- 现有返回字段足够标注“仅高标准农田／非永久基本农田”以及相反归属。
- 返回值不含每块差分对应的原始要素 OID、原始业务属性。若“保留属性”还包括追溯具体原地块的权属、项目、编号等，需要后端补充来源要素关联及属性；前端不能根据面积或包围盒猜测。

## 2. 自定义名称上传 SHP：已按用户选择接入前端解析

本轮已实现：选择同名 `.shp/.dbf`（建议带 `.prj/.shx/.cpg`），自定义名称；通过 Web Worker 解析，转换为 WGS84 后以原生 Leaflet 图层显示，缩放平移不重新请求。中文支持 CPG、UTF-8 和 GB18030，长整数编号按文本保留。缺少或无效的坐标系必须手动指定，不能猜测。

图层及其名称、显隐、铺满／边界模式保存在 IndexedDB，按账号、部门和专题隔离。当前限单组 50MB、5000 条记录、50 万坐标点，每个专题最多 10 个上传图层。图层仅保存在当前浏览器，不会发布为后端共享服务。点线图层可显示，面积分析只接受面图层。

以下说明保留现有后端能力边界，后端共享上传并非本轮前置条件。

现有 `POST /api/v1/spatial/spot/compare/upload` 是“上传并同时对比”接口：

- multipart 文件字段 `files`，至少 `.shp + .dbf`，可以随同提交 `.shx/.prj/.cpg`。
- 必传 `geometryA` 和 `geometryB` 两个 WGS84 GeoJSON 字符串；不能只上传并取回完整预览图层。
- 文档限定源坐标系 `CGCS2000_3_Degree_GK_CM_120E`。尚无上传图层名、临时图层 ID、过期时间、独立预览/查询/删除接口。
- 识别图斑导入预览接口绑定业务场景，且仅返回前 50 条预览，不能作为专题完整图层导入接口复用。
- 当前 `/overlay` 的输入只接受 `serviceId/layerId`，不能引用上传图层。

### 建议后端最小补充

1. 通用临时上传解析接口，接收 `files`、`name`、部门视角及明确的源坐标系；返回完整 WGS84 FeatureCollection、字段与中文别名、要素数、范围、解析警告，以及可用于分析的 `uploadId`。若文件较大，应通过分页/流式几何读取而非返回截断预览。
2. 明确允许的文件、单次大小/要素数、支持的坐标系、缺少 `.prj` 的处理方式；不能静默按错误坐标系解释。若当前只能支持 120E 的 CGCS2000，应明确返回并校验。
3. `/overlay` 的 A/B 输入支持“发布服务引用”或“临时上传 ID”。上传数据的作用域、保存期限及刷新后的恢复策略应明确；前端显示名称可以先保存在当前会话，但持久化名称及几何需有后端或本地存储支持。

已采用路线：前端使用 `shpjs` 与 `proj4` 解析 SHP/DBF 和投影，仅负责格式转换、显示及准备完整 WGS84 几何；通过现有 `/spot/compare` 将几何交给后端计算，浏览器不做叠置。发布图层通过完整 ID 索引分批读取全部几何，检查服务截断，使用 `@terraformer/arcgis` 保留多部件和内环。请求几何总大小上限 20MB；超限须先属性筛选或简化数据。

## 3. 新功能建议名称：范围覆盖分析

输入上传规划范围 U，选择目标图层 T。应输出：

- 范围内：`U ∩ T`，带裁切后的几何、面积及占上传范围的比例。
- 范围外：`U − T`，带裁切后的几何、面积及比例。
- 只研究 U 的覆盖情况；`T − U` 不计入“范围外”。

### 现有上传接口的语义不满足精确覆盖面积

可复算测试：上传一个 200m×100m 的矩形（20,000㎡），目标 A 仅覆盖其左半（10,000㎡），目标 B 放在远处。

实际 `/spot/compare/upload` 返回：`inA.spotCount=1`、`inA.areaSqm=20000`、`inNone.areaSqm=0`，几何仍为整个上传矩形。将 A、B 设成同一左半目标时，返回 `inBoth.areaSqm=20000`。

因此该接口实现的是“上传整图斑是否与 A/B 相交”的四分类；“仅部分相交”也会计入整块面积。它并非裁切后的实际覆盖／未覆盖分析，不能将这些面积标成已覆盖面积。

同一组测试使用 `POST /api/v1/spatial/spot/compare`、传入完整 U 与左半 T 时，`both.areaSqm=10000`、`aOnly.areaSqm=10000`，计算能力本身已经存在。

### 本轮接入方式与实测

范围覆盖分析已经使用现有 `/spot/compare`：A 为上传范围，B 可选上传面图层或已发布面图层。一个结果图层包含 `both`（范围内，绿色）及 `aOnly`（范围外，橙色），不展示 `bOnly`。面积采用后端返回值，占比以完整上传范围面积为分母；阈值过滤后未输出的面积另列。结果可导出 GeoJSON，含上传范围及目标图层名称。

浏览器实测：上传 200m×100m 的 EPSG:4549 矩形和其左半矩形，返回范围内 10000㎡、范围外 10000㎡，各占 50%，地图显示两块真实裁切几何。同一上传矩形与发布的永久基本农田图层（完整 1123 要素）比较，在无交集位置返回范围内 0㎡、范围外 20000㎡。上传图层也可参与对称差分；上述矩形返回一个 10000㎡ 的 A_ONLY 结果，带明确来源及排除图层名称。

分析成功后原图层仅取消勾选，配置与上传文件不删除；失败保留原图层与上次结果，明确显示接口错误。上传状态经刷新恢复的浏览器测试通过。已有发布图层间的差分仍使用 `/overlay` 引用服务，避免无谓传输完整几何。

### 后续后端共享与原属性追溯

优先：后端提供上传临时图层与目标服务引用的覆盖分析。可复用现有几何运算，但返回 `inside/outside` 的真实裁切结果，保留上传地块的原始属性及来源 ID。统计至少包括上传范围面积、范围内/外面积（㎡、亩）、覆盖率、结果图斑数、面积投影、实际阈值；阈值过滤的面积应另行说明，避免比例加起来无法核对。

也可在上传解析问题解决后，调用现有 `/spot/compare`：令 A=U、B=T，将 `both` 展示为范围内，将 `aOnly` 展示为范围外。此方案无需新增几何计算接口，但前端需获取并传输两侧完整几何，适合规模受控的数据；该接口不透传原始 SHP 属性，需要另外解决属性关联。

## 4. 本次实测需修正的接口细节

- OpenAPI 的 `SpatialSpotCompareVO` 把字段写成 `aonly/bonly`，实际响应是 `aOnly/bOnly`，建议统一文档，避免客户端按文档读取不到数据。
- `/spot/compare` 在 `minAreaSqm=0` 的矩形测试中，B 完全包含于 A，但 `bOnly.featureCollection` 仍有两个 `areaSqm=0` 的退化 Polygon；坐标中有连续重复点，面积合计为 0。建议投影／精度处理后剔除非面、空面及零面积图斑，且统计中的图斑数同步修正。前端不得将这些退化结果当作有效差异。
- 现有差分导出默认上限为 5000 图斑；大数据量需要明确分页或分块导出，而不是让用户误认为完整图层已加载。本轮仍显式反馈超限错误，不偷偷改用合并 DIFF 丢失来源。

测试采用 EPSG:4549 的 SHP，携带 `NAME/ORIG_ID` 两个诊断属性；上传对比结果确实透传了这两个字段，返回几何已转 WGS84。
