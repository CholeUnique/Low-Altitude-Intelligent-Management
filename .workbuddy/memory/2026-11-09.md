## 权限管理界面配色统一（PermissionManagementPanel.vue）
- 现象：用户反馈「界面内的颜色不协调」；先按布局理解偏了，澄清后确认是配色。
- 客观诊断 1（色相）：对截图内容区做 HSV 统计（s>0.3、v>0.18），98.99% 落在 hue 195–210 → 不是色相打架，是同色相内层级失控。
- 客观诊断 2（根因，关键）：先按「自建 3 层表面」重做了一版（#0a2434 / #0d2d41 / #071d2b），结果**更糟**——范围条与表头变成近乎全黑的条带。采样后发现 `#071d2b` 生效了，但卡片背景没生效：`src/styles/system/_resources.scss:159` 有
  `#app .management-content :is(.scene-panel,.user-card,.permission-card,...) { background: var(--ui-panel-background); ... }`，特异性 (1,2,0) 压过组件 scoped 的 (0,2,0)。卡片实际渲染的是 `--ui-panel-background`（半透明浅一档 ≈ #0e3349），于是自建的实色深底就成了「黑洞」。
- 真正结论：该面板是**自建整套深色色板**，与后台其它页（用户管理/部门管理/元数据/地图服务，全部走 `--ui-*` 令牌）是两套体系 → 这才是长期「不协调」的原因。
- 最终修复：整块 `<style scoped>` 改为**全量使用设计令牌**，几乎不再出现字面色值：
  - 表面 `--ui-panel-background` / `--ui-surface-raised` / `--ui-input` / `--ui-hover` / `--ui-selected`
  - 边框 `--ui-border` / `--ui-divider`；圆角 `--ui-radius` / `--ui-control-radius`；阴影 `--ui-shadow`；动效 `--ui-motion`
  - 文字 `--ui-text` / `--ui-body` / `--ui-muted`；强调 `--ui-accent` / `--ui-link` / `--ui-action`；语义 `--ui-success` / `--ui-warning` / `--ui-danger`
  - 仅保留头像渐变 `#12708c→#1fabc9` 与头像文字 `#eafcff`（令牌里没有头像色）
- 校验：产物 CSS 中 `.permission-card` / `.scope-note` / `.matrix-head` / `.primary` 均已为 `var(--ui-*)`；`#071d2b` 的 9 处残留全部属于其它组件（data-v 不同）。
- 经验沉淀（重要）：**本项目「后台管理」类页面一律走 `--ui-*` 令牌**（`_tokens.scss` 定义，`_resources.scss` / `_controls.scss` / `_operations.scss` 做统一覆盖）。给这类页面调色时**不要自建色板**——全局规则的特异性往往高于组件 scoped，自建色值会与全局表面色打架，表现为某些块过深（黑洞）或过亮（白条）。改色前先查 `src/styles/system/` 里有没有针对该组件的全局覆盖。
- 经验 2：判断「配色不协调」先做色相/明度统计；若色相高度集中，问题在**层级与强调色冗余**，或**与全局令牌体系冲突**，而不是换主色。

### 后续修补：表头色带两端留白
- 现象：换成令牌后，`功能权限` 表头色带左右两端各有一条 16px 的浅色竖条（用户红框标出），因为 `.permission-matrix{padding:0 16px 16px}` 让 `.matrix-head` 只能铺到内容宽。
- 修复：`.matrix-head` 加 `margin:0 -16px;padding:0 16px`——负外边距把背景撑到内边距区，等量 padding 让网格列仍与原位置对齐（220px + 1fr 不变），粘顶滚动与窄屏断点都不受影响。
- 通用手法：**滚动容器有水平内边距、而子元素需要整幅背景时，用 `margin-inline:-padding; padding-inline:padding` 做「出血」，比把 padding 挪到子元素上更省事、且不牵动其它行**。
