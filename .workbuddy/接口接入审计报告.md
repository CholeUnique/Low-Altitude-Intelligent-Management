## 第 0 类：紧急 —— 前端调用了不存在的接口（1 个）

**`POST /v1/biz/facility/report/image/view`**（`src/api/facility.ts:110`，`getFacilityReportImage`）

- 使用方：`src/components/FacilityReportImageGallery.vue:19`（设施问题上报的照片墙）
- 事实：swagger 全文检索 `report/image`、`imageId`、`FacilityReportImage` 均 **0 命中**；schema 中只有 `BizImageVO`（任务影像），不是上报照片。
- 风险：这是**运行时 404**，不是"没做功能"，而是"做了但会失败"。
- 判断：大概率是后端已实现但 swagger 未更新（前端按后端口头约定写的），需向后端确认。
- 建议：先问后端要该接口的真实路径与入参。若确实未实现，前端需降级（照片墙显示"暂不支持查看"），否则每次打开都报错。

## 第 2 类：建议接入 —— 有明确业务价值（7 个）

### 2.1 高价值 / 建议优先

**① `POST /v1/uav/asset/page` 建模成果分页**
- 价值：**整块能力缺失**。后端有完整的二三维建模成果（2D/3D/高斯泼溅），含 `boundingGeojson`（可直接在 Leaflet 叠加）、`coverUrl`、`serviceUrl`、`gsd`、`area`/`areaMu`。
- 现状：前端 `AlgorithmRepositoryView` 是算法仓库，与建模成果无关；`/data-results` 只做成果批次与影像。
- 接入建议：在「数据管理」加第 3 个 tab「建模成果」，卡片列表 + 地图叠加 `boundingGeojson`。工作量中等，收益大。

**② `POST /v1/uav/asset/detail` + `download` + `download/file`**
- 与 ① 配套。detail 给文件清单（含 `downloadStatus` / `localFileExists`），download 是幂等触发下载。
- 注意：`download` / `download/file` 需**管理员权限**，普通用户只能看状态。按钮要按 `role` 显隐。

**③ `POST /v1/biz/statistics/count-by-dept` + `POST /v1/uav/statistics/count-by-dept` 部门横向对比**
- 价值：管理员视角的部门排行，字段齐全（场景数/任务数/异常数/违占面积含亩/成果数）。
- 接入建议：放在「后台管理」新增 `analytics` 分节，或首页在 ADMIN 时多一个排行面板。注意仅 ADMIN，403 要兜住。

**④ `POST /v1/workflow/transfer` 转办**
- 关键发现：**请求体与已接入的 `reassign` 完全一致**（都是 `{nodeInstId, targetUserId}`），`WfTransferReq` 是同一个 schema。
- 现状：`non-grain-assignment.ts:36` 只调了 `reassign`（改派）。转办在 `task-workflow-state.ts:43` 的注释里提到过，但没接口。
- 差异：改派 = 换人办理（跨部门/上级指派）；转办 = 转给同级同部门同事（跨部门须同 parent）。
- 接入成本：**最低**。复制一个函数，把 URL 换掉即可。建议在任务详情的工作流节点菜单里，根据是否同部门决定显示「转办」还是「改派」。

### 2.2 中等价值

**⑤ `POST /v1/uav/project/page` + `/detail`**
- 价值：当前只有 `project/options`（下拉用）。真正的项目列表页缺失，无法看项目概览（封面/中心点/同步时间）。
- 建议：机队总览里加项目切换或独立项目卡，优先级可低于 ①。

**⑥ `POST /v1/uav/dept-exclude/*`（5 个：add / batch / page / preview / remove）**
- 价值：无人机数据的**跨部门可见性例外**（默认全可见，按例外排除）。这是数据权限治理能力。
- 建议：并入「后台管理 → 权限管理」，做成一个"数据可见性"子页。`preview` 能预览级联影响，很适合做成二次确认弹窗。
- 注意：`bizType` 只支持 PLAN/TASK/DEVICE/WAYLINE，不支持 PROJECT。

**⑦ `POST /v1/uav/device/detail`**
- 价值：目前 `device/page` 列表有数据，但点进去没详情（SN 维度的完整信息）。
- 建议：机队总览的设备卡点击 → 详情抽屉。成本低。

## 第 4 类：二进制流，最容易漏但很重要（3 个）

**`GET /v1/uav/media/file/{mediaId}`** 和 **`GET /v1/uav/media/srt/{mediaId}`**
- 注意：这是**全项目唯一两个 GET + 二进制流**接口，已有先例——`flight-review.ts:181` 已经接了 srt 版本，说明模式是通的。
- 但 `media/file/{mediaId}` 未接。它是"三方临时签名 URL 失效后的稳定访问"兜底。
- 接入建议：`<img>`/`<video>` 不能带 Authorization 头，所以该接口支持 **`?token=` 查询参数**。需要在 `client.ts` 加一个 `appendAuthToken(url)` 工具，否则会 401。
- **建议优先做**：目前素材预览完全依赖三方签名 URL，一旦过期就是空白，体验断崖。

**`POST /v1/biz/result/download`**
- 返回二进制流，错误体是 JSON（和 `facility/qrcode` 同款惯例）。
- 现状：`governance-result.ts` 只有 page/detail/image-list，**没有下载**。成果批次详情里"下载"按钮点了没反应或不存在。
- 接入建议：直接复用 `FacilityQrcodeDialog` 里已有的 Blob + `blob.type.includes('json')` 错误解析模式，`URL.createObjectURL` 后触发 `<a download>`。

## 两个共性技术风险（接入前必须知道）

1. **二进制流接口的错误体是 JSON**，不是 HTTP 错误码。现有 `FacilityQrcodeDialog` 已踩过坑并解决（`blob.type.includes('json')` → `readBlobError()`），新接口复用即可。
2. **int64 大整数**：`client.ts` 的 `parseJsonWithSafeIntegers` 已做字符串感知扫描。新增接口只要走 `apiClient` 就自动安全，**不要绕过 client 直接用 axios/fetch**，否则 ID 会被 JS 精度截断。
